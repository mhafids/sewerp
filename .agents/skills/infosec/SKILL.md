# Infosec & System Security Engineering

This skill equips agents with domain-specific security audit protocols, threat modeling patterns, and compliance verification standards tailored to SewERP's architecture and regulatory requirements.

---

## 1. Core Security Principles & Compliance

When auditing, reviewing, or implementing any code, configuration, or API endpoint in SewERP, enforce these 4 core tenets:

1. **Principle of Least Privilege (PoLP)**:
   - Ensure users and service tokens receive only the minimum permissions necessary.
   - Enforce fine-grained RBAC action checks (`view`, `create`, `update`, `delete`, `export`, `import`, plus business actions like `approve`, `print`).
2. **Defense-in-Depth (Pertahanan Berlapis)**:
   - Apply authorization and multi-tenancy controls at multiple layers: Nginx reverse proxy, Gin middleware, domain usecases, and PostgreSQL Row-Level Security (RLS).
3. **Zero Plaintext Secrets**:
   - Never store API secret keys (e.g. Xendit), webhook tokens, passwords, or PII in plaintext.
   - Strictly prohibit committing credentials into git repositories.
4. **Zero Trust Boundary**:
   - Re-authenticate and validate every request from browsers, webhooks, or background queues.
   - Never trust client-supplied input.

**Regulatory Acronyms & Standards**:
- **UU PDP No. 27 Tahun 2022** (Indonesian Personal Data Protection Law).
- **OWASP Top 10** & **OWASP API Security Top 10**.

## 3. Garment CAD Pattern & Tech Pack Security (Level 4 Strict)

Garment patterns and Tech Packs are high-value proprietary intellectual property. Enforce the following:

1. **Private S3 / MinIO Bucket Configuration**:
   - Disable all public anonymous read/write access.
   - Storage keys MUST use randomized UUIDv7 paths:
     ```text
     s3://sewerp-patterns/{tenant_id}/{pattern_id}/{uuidv7}.dxf
     ```
   - Never use original client-supplied filenames as S3 storage keys (prevents path traversal and client disclosure).
2. **Short-Lived Presigned URLs**:
   - Downloads and browser previews must strictly use on-demand Presigned URLs generated by the Go backend.
   - **TTL Limit**: Maximum duration of **15 minutes (900 seconds)**.
3. **Dynamic Visual Watermarking**:
   - For browser previews of PDF/mockup files, verify that a semi-transparent diagonal watermark is stamped across the preview:
     ```text
     [Tenant Name] | Confidential | [User Name] | [Timestamp UTC]
     ```
4. **Audit Logging**:
   - Record an immutable log entry in `pattern_download_logs` containing `user_id`, `file_id`, `ip_address`, and `downloaded_at`.

## 4. Payment Gateway & Webhook Security (`oms` / SPEC-009)

When auditing payment gateway endpoints (e.g. Xendit, BI-Fast, VA, QRIS):

1. **Credential Encryption**:
   - API Secret Keys and Webhook verification tokens in `tenant_payment_gateways` must be encrypted using **AES-256-GCM** before database insertion.
2. **Webhook Signature Verification**:
   - Verify incoming webhook callbacks using HMAC SHA-256 signatures with constant-time comparison (`crypto/subtle.ConstantTimeCompare`).
3. **Idempotency Enforcement**:
   - Enforce unique event IDs (`event_id` or `idempotency_key`) to prevent replay attacks and double-crediting.
4. **Anti-Tampering Financial Calculations**:
   - Final prices, DP requirements, and discounts MUST be calculated purely on the server using `BIGINT` integer arithmetic. Never trust client-submitted prices.

## 5. Multi-Tenancy & Row-Level Security (RLS)

1. **Mandatory Tenant Clause**:
   - Verify that all database queries include `tenant_id = $1`.
2. **Database RLS Policies**:
   - Enable PostgreSQL Row-Level Security on sensitive transactional tables (`sales_orders`, `payroll_slips`, `tenant_payment_gateways`).
3. **Context Injection & Validation**:
   - Ensure Gin middleware extracts `tenant_id` from verified session tokens, injects it into `context.Context`, and rejects any request lacking a valid tenant scope.

---

## 6. HTTP & Session Security Checklist

1. **Secure Session Cookies**:
   - Session cookies MUST be marked `HttpOnly; Secure; SameSite=Lax`.
   - Lifespan should not exceed 1 work shift (**8 hours**).
2. **Security Headers**:
   - Verify Nginx and Gin middleware emit:
     - `X-Frame-Options: DENY`
     - `X-Content-Type-Options: nosniff`
     - `X-XSS-Protection: 1; mode=block`
     - `Referrer-Policy: strict-origin-when-cross-origin`
     - `Content-Security-Policy: default-src 'self'; ...`
     - `Strict-Transport-Security: max-age=31536000; includeSubDomains; preload`
3. **Zerolog Redaction Hook**:
   - Ensure the JSON logger masks sensitive keys: `password`, `secret_key`, `webhook_token`, `authorization`, `phone_whatsapp`.

## 7. Security Audit Verification Commands

Run these automated checks during security reviews:

```bash
# 1. Check for committed plaintext secrets or API keys
trufflehog git file://. --since-commit HEAD~5 2>/dev/null || true

# 2. Audit Go dependencies for known vulnerabilities (CVEs)
govulncheck ./... 2>/dev/null || go list -m all

# 3. Verify PostgreSQL RLS and tenant_id isolation in migrations
grep -rn "tenant_id" backend/migrations/
```
